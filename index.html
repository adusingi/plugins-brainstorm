Brainstorm · Kazoku × Emily · October 2026

Every tile is a plugin and Kazoku becomes a preset

Emily stays the master of all family data. Kazoku stops being a separate app: it becomes a saved layout of plugins on a thin screen app, “Kazoku, powered by Emily”. A family can keep today's fridge screen exactly, or swap Weather for Surf and Tides.

Mock screens with example values. The tag on each tile names the plugin behind it.

What a plugin is

Five parts. Emily runs the data; the screen only draws.

How it fits together

The screen asks Emily for one thing: its layout, with every card's data filled in.

The screen app never calls a weather or tide provider itself, and holds no family data. A second screen app with another name could draw the same screens.

Setting up a screen

From an Emily account to a surfer's fridge.

  1. Sign in with EmilyThe same account as the Emily app.
  2. Pick a presetKazoku Classic gives today's screen, exactly.
  3. Remove WeatherOne tap on the tile.
  4. Add Surf and TidesFrom the plugin catalog.
  5. Drop a pin on the surf spotThe only setting both plugins need.

The fridge now shows swell and tides where the weather used to be.

What already exists

Most of the pieces are in the two codebases today.

  • Kazoku's board is already assembled from parts. GET /board returns people, occurrences, chores, shopping and weather. Each part becomes a plugin.kazoku-dashboard · server/board/board.js
  • Emily's AI already calls two outside-world tools: weather (Open-Meteo) and crypto_price (CoinGecko). The crypto tool is the seed of a blockchain-metrics plugin.emily-wave · server/ai/tools.js
  • Surf and tides can use the provider Kazoku's weather already uses. The Open-Meteo Marine API offers wave_height, swell_wave_height, wave_period and sea_level_height_msl, which includes tides.
    Two checks before building. The provider states that “accuracy at coastal areas is limited” and that the data is not suitable for coastal navigation, so the card should say so. Emily is a paid product, so it falls under Open-Meteo's commercial licence, which requires an API key.
    open-meteo.com · Marine Weather API documentation

Four decisions for the brainstorm

Each one shapes the plugin format. The recommendation is a starting point for discussion.

Who draws the card?

Option AEach plugin ships its own screen code. MagicMirror² modules work this way: a browser file plus an optional server helper.
Option B RecommendedThe plugin returns data in a standard card shape, and every screen knows how to draw those shapes. No outside code runs on the fridge, and the same card works on a phone, and later in a CLI or for an AI agent. Surf, tides and weather share the hourly strip.

Who writes plugins?

Option AAnyone, from day one.
Option B RecommendedOur team first, built into Emily. The plugin format is designed so that others could publish later.

What can a plugin see?

Option AEverything in the family's account.
Option B RecommendedOnly what it declares, approved on install. Events and chores ask for family data. Surf, tides and crypto need only a location or a coin list.

Where does the layout live?

Option AOne layout per family.
Option B RecommendedOne per screen. The fridge keeps the family layout while a surfer's phone shows tides. Presets are starting layouts (Kazoku Classic, Surf, Crypto desk), each with its own name.

How this fits what was already decided

  • Emily is the master. Plugins live in Emily, so moving a Kazoku module to Emily means turning it into a plugin.
  • Kazoku is beta: its data can be reset and nothing is copied over.
  • Emily is in production: every change to it adds, never removes.

Parked until this settles

  • When the AI adds something from chat: ask first, or save straight away?
  • Which Kazoku module becomes the first plugin.

Proposed next step

A clickable prototype of the setup flow: pick a preset, remove Weather, add Surf and Tides, and see the fridge screen change. It is cheap to build and quick to react to before any plugin format is fixed.
